# Phase 2 · prototype implementation contract

User-authorized throwaway UI experiment, not homepage integration. Audit saved first as PR #6 / 613f4d8 against preview/xuanyi-2-3. Experiment branch: experiment/creative-direction-abc, based on audit branch. Prototype PR will target audit branch to keep its diff limited to the experiment.

Actual Skill invocation: read `.agents/skills/prototype/SKILL.md` + `UI.md`, select UI branch, three structurally different variants on `/lab/creative-direction/?variant=A|B|C`, shared floating URL switcher with keyboard support, runtime state visible. Existing route cannot host replacement because it is the stable comparison; use existing Lab routing convention. Do not automatically promote any variant.

A: typography and a sculpture occupy the same editorial space; material reveal and exhibit/gallery handoff. B: X becomes the structure of a continuous canvas; scroll folds towards real project windows. C: real Router, ATLAS and story artifacts compose the first viewport; a short connection response follows project selection. Each variant owns its own CSS/layout, mobile design, entry and scroll sequence. Root implements only switcher, common actual 3D rendering primitive and scoped shell. No new animation framework or external design assets.

Shared interface: `import { Sculpture } from './sculpture'`, `<Sculpture variant="A" className="..." />`, likewise B/C. This is a real mesh with perspective, surface normals, procedural environment light and pointer/touch/click/keyboard pose response, not the old Sky SVG. It pauses after settling, respects reduced motion and disposes GL resources. Variants can dispatch a `cd-sculpture-change` CustomEvent from their nearest section, detail `{progress:0..1,energy?:0..1}` to request a structural response.

Implement each variant as named exported `VariantA/B/C` in variant-a/b/c.tsx plus variant-a/b/c.css. Root `.cd-root[data-variant]`; variant own `.cd-a/.cd-b/.cd-c`. Shared sculpture class `.cd-sculpture`, canvas fills provided box. Each artifact uses current project data and existing public/projects media with source/licensing boundaries unchanged. At least A reuses LivingGallery; original implementation stays untouched. Data interaction controls marked `data-direction-interaction` prevent switcher arrow-key conflicts.

Verification: build/typecheck/existing unit tests, actual Chromium + available WebKit at1440×900 and390×844, initial/interactive/scroll/back video for each variant, screenshots, reduced-motion, touch, keyboard, route switch, real details/back, resource cleanup, relative performance. Independent design review sees running renders and reports strengths/weaknesses without treating code complexity as art. Record actual limits rather than claiming true-device or all-pass results.
